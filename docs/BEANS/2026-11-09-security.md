# Security

As a first pass at security analysis, consider static code analysis 
tools which inspect codebases for security holes. This can then be 
augmented by tools which instrument and/or exercise the code in a 
live environment, if that provides clearer insights than static 
analysis alone.

Example tools that might fit this requirement are: `ts-morph`, 
`Opengrep`, `Jazzer.js`, `fast-check`, and `Playwright`.

The security analysis itself should be deterministic, but it should 
have custom rules and tests which an LLM/agent could run and augment 
by discovering and constructing new rules and tests.

Running panopticode-ng on an arbitrary TypeScript repo may require a 
tool like `Railpack`.
