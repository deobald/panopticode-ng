# Panopticode C#

Inspect code health, correctness and security findings using a native .NET CLI.
Produces an interactive offline `report.html` and C#-specific, version-1
`report.json`. Works for general C# projects; its initial real-world target is
a legacy application being hardened for retirement. No Node runtime is required.

## Install and run

Requires the .NET 10 SDK. From the repository root:

```sh
dotnet restore csharp/src/Panopticode.CSharp.csproj --locked-mode
dotnet build csharp/src/Panopticode.CSharp.csproj --no-restore
dotnet csharp/src/bin/Debug/net10.0/panopticode-csharp.dll /path/to/project --out reports/csharp
```

Open `reports/csharp/report.html`. The report contains directory/file/region
treemaps, search, metric selection, sortable source locations, type structure,
findings, duplicate ranges, coverage and pass statuses. It follows system
light/dark mode and works without a server or network access. Browser JavaScript
is embedded in the report; Node is not needed to build or run the analyzer.
The treemap partition function is embedded directly from the existing
`ts/src/web/treemap.js` source at build time.

All passes run by default; unavailable evidence fails visibly while the other
passes continue and reports are written. Exit codes are 0 for successful passes
(findings allowed), 1 for failed evidence, and 2 for CLI/setup errors. `runs/`
retains imported artifacts, command logs and error details for each invocation.
Reports are local build artifacts and are ignored by Git.

| Pass | Tool | Evidence |
| --- | --- | --- |
| Syntax | Roslyn 5.9 | Physical lines, statements, explicitly defined syntax CCN, nesting, parameter counts, type structure. Runs independently of MSBuild. |
| Diagnostics | Microsoft.NetAnalyzers 10.0.403 and Meziantou.Analyzer 3.0.322 | Compiler diagnostics plus selected correctness, reliability and security rules. |
| Semantic metrics | Microsoft.CodeAnalysis.Metrics 5.6 | Source/executable lines, cyclomatic complexity, class coupling and inheritance depth. Uses its managed metric APIs, not its Windows command-line executable. |
| Duplication | Roslyn token detector, profile v1 | Exact token sequences, keeping identifiers/literals and ignoring comments/whitespace. Native .NET implementation. |
| Coverage | Project Coverlet or configured test runner | Cobertura line evidence; also imports existing dotCover DetailedXML. |

Resolved NuGet versions are locked. Tool versions and counting definitions
travel with each report. Syntax CCN and Microsoft CCN have different definitions
and stay separate. Maintainability index is omitted. There is no aggregate
health score, automatic fix, formatting pass or automatic deletion.

## Project scope and diagnostic policy

The target can be a directory, `.csproj`, `.sln` or `.slnx`. For a directory,
semantic passes prefer a root `.sln`, then `.slnx`, then `.csproj`. Ambiguous
selection fails with an instruction to use `--project FILE`. Restore the
target's own dependencies with its usual toolchain before semantic analysis.
The analyzer does not install or edit the target's package references.

Syntax discovery inventories `.cs` files below the target root, including tests
and migrations. It excludes `.git`, `.vs`, `.idea`, `bin`, `obj`, `packages`,
`node_modules`, `vendor`, `reports`, `TestResults`, the output directory,
symlinks, `*.g.cs`, `*.g.i.cs`, `*.designer.cs`, and files with an
`<auto-generated` header in their first 1,024 characters. Repeat `--exclude DIR`
to exclude root-relative paths, or a directory name at any depth. Razor/XAML,
JavaScript, SQL and other non-C# files are outside this package's measurements.

Syntax uses `DEBUG;TRACE` symbols by default. Override with `--define 'A;B'`;
inactive preprocessor branches are outside its measurements and duplication.
Semantic passes use evaluated project settings and warn when symbols differ.
Use `--framework TFM` to select a semantic/test framework in multitargeted
projects. Source inventory can include files outside evaluated Compile items;
those files keep unknown diagnostic evidence. Project references are loaded for
semantics even when their files are outside the report inventory.

`--profile baseline` (default) runs a versioned allowlist in
`src/ProjectAnalysis.cs`: CA2000/2007/2008, CA2012–2014, CA2016–2018,
CA2021/2022, CA2200/2202, CA3001–3012 and the selected CA30xx/CA53xx/CA54xx
security rules listed there; Meziantou MA0009, MA0022, MA0040, MA0042,
MA0055, MA0064 and MA0134. Only IDs supported by the pinned tools run.
It excludes formatting/naming rules and uses the bundled analyzers rather than
the project's analyzer references. Baseline rule severities override project
analyzer configuration; compiler/source suppressions still apply.
`--profile project` also runs the target's referenced diagnostic analyzers and
uses its analyzer options and policy; that policy can include style rules.
Source generators used during compilation remain project-owned in both modes.

Compiler errors fail the diagnostic pass while retaining available findings.
Semantic metrics require an error-free compilation. A failed pass does not
establish clean code even when no findings are available. Security checks are
static review evidence, not a complete vulnerability audit. Reflection, routes,
serialization and external consumers complicate unused-code reasoning: compiler
unused-field/local warnings do not establish safe deletion of public APIs or
unused private methods. Whole-solution dead-code analysis is not implemented.

## Coverage and imports

When a compatible Coverlet package is already referenced by the target test
projects, coverage runs `dotnet test --no-restore` with either the VSTest
`coverlet.collector` driver or the MTP `coverlet.MTP` driver and a fresh results
directory. The target needs its own test SDK/runner/runtime. Projects using
mixed runners, central references not discoverable in project XML, legacy
Framework test tools or other workflows should configure a command.

Create `panopticode.config.json` in the target, or pass `--config FILE` to keep
configuration elsewhere:

```json
{
  "version": 1,
  "coverage": {
    "command": ["dotnet", "test", "tests/Tests.csproj", "--collect", "XPlat Code Coverage", "--results-directory", "coverage"],
    "reports": ["coverage/session/coverage.cobertura.xml"]
  },
  "pathMappings": {
    "C:/agent/work/application": "."
  }
}
```

Use the actual output filenames produced by your workflow; generated VSTest
session directories vary. Paths inside configuration resolve against the target.
Commands are argument arrays executed without a shell, in the target directory.
They have a timeout; timed-out subprocess trees are killed. A command must exit
zero and create or change every expected report. Unchanged/stale files and
failed commands are rejected. Existing reports can instead be imported directly:

```sh
dotnet csharp/src/bin/Debug/net10.0/panopticode-csharp.dll /path/to/project \
  --out reports/csharp --sarif evidence/diagnostics.sarif \
  --metrics evidence/metrics.xml --coverage evidence/coverage.cobertura.xml
```

Imports and the CLI `--config` path resolve against the invoking directory.
Imports are SARIF 2.1.0, Microsoft CodeMetricsReport XML, Cobertura XML, dotCover
DetailedXML, and (with `--duplication FILE`) the `duplicates` array extracted
from this package's JSON. SARIF artifact lists and result locations establish
known diagnostic scope; absent files remain unknown. Coverage reports from
multiple configured paths merge by source line with any hit counted as covered.
Unknown source paths are not guessed by basename. Use `pathMappings` for reports
generated on Windows or another checkout; forward slashes work for Windows roots.
Imported producer versions and source freshness remain unverified.

`--no-diagnostics`, `--no-metrics`, `--no-coverage`, and `--no-duplication`
override imports. Other options include `--name`, `--timeout SECONDS` (default
300), `--exclude`, `--define`, `--project`, `--framework`, `--profile` and `--help`.
Syntax always runs; files that fail parsing stay visible with unknown metrics.
Duplication fails if any scoped source cannot parse.

The duplication detector uses rolling token hashes with exact text verification,
50-token/5-line minima, same-file overlap exclusion and representative matches
instead of every possible pair. Overlapping duplicated lines count once.
Resource limits (5 million candidate comparisons or 100,000 representative
matches) fail explicitly rather than producing a truncated clean result.

## Learning Blade

The initial target has classic ASP.NET MVC/.NET Framework 4.6.2 projects. Its
`Tests/` tree contains NUnit unit/integration tests, and
`Tests/Scripts/RunTestSuiteAndGenerateCoverage.ps1` runs NUnit Console with
dotCover 2023.2.3, exporting `coverage/LearningBladeTestCoverage.xml` in
DetailedXML format. No generated coverage artifact was present in the checkout
when inspected. Test presence is not measured coverage.

From this repository, with .NET available on PATH:

```sh
dotnet csharp/src/bin/Debug/net10.0/panopticode-csharp.dll ../learning-blade \
  --out csharp/reports/learning-blade
```

On macOS the source and duplication passes work. Semantic passes require its
Windows reference assemblies, restored dependencies and Visual Studio web build
targets; coverage requires its Windows test environment and any integration
services. These passes fail visibly on an unsupported host. Collect SARIF and
Microsoft Metrics XML on Windows, and import the existing workflow's dotCover
DetailedXML with path mappings. This package does not change Learning Blade or
attempt to run its service-dependent integration tests on macOS.

## Validate

```sh
dotnet restore csharp/tests/Panopticode.CSharp.Tests.csproj --locked-mode
dotnet run --project csharp/tests/Panopticode.CSharp.Tests.csproj --no-restore
dotnet restore csharp/examples/demo/Demo.csproj
dotnet csharp/src/bin/Debug/net10.0/panopticode-csharp.dll csharp/examples/demo \
  --out csharp/reports/demo --no-coverage
dotnet run --project csharp/tests/Panopticode.CSharp.Tests.csproj --no-restore -- \
  --browser csharp/reports/demo/report.html
```

The integration tests execute real Roslyn/MSBuild and metric APIs, verify a
security finding, exercise imports, source scope, missing evidence, fresh/stale
commands, timeouts and HTML escaping. MSBuildWorkspace needs local IPC sockets.
Browser checks use installed Google Chrome (override `PANOPTICODE_CHROME`),
checking offline interaction in light/dark and mobile layouts. They do not
measure test coverage. The analyzer itself has not been validated on Windows.
